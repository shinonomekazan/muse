# 仕様書 — Todoリスト（空間Todo）

Muse に再現させるための詳細仕様。人間が読んで「同じものか」を判定する基準にも使う。
再現指示そのものは [PROMPT.md](./PROMPT.md) が正本で、この文書はその補足である。

## コンセプト

Todo を「期限のリスト」ではなく「時間の空間」として扱う。

```
← 過去（完了履歴）          今日          未来（先送り） →
… 2日前に完了 | 昨日完了 | 今日やる | 明日までやらない | 2日後までやらない …
```

- 右へ置くことは「やらない宣言」である。先送りしたタスクは、今日の画面に存在自体が現れない
- 左へ流れるのは完了したタスクだけである。未完了タスクは今日に残り続ける
- 設計の動機: 明日やるものが目に入ると気になり、昨日完了したものをいちいち見る必要もない、という人間の認識の性質

## データモデル

各タスクが持つ情報の論理モデル（実装方法は問わない）:

| 項目 | 内容 |
|---|---|
| タイトル | 必須。追加時はこれだけで作れる |
| 詳細メモ | 任意のテキスト |
| 完了状態 | 完了／未完了 |
| 完了日 | 完了した暦日。未完了のときは空 |
| 先送り日数 | 0以上の整数。概念上は上限なし（実装上の技術的上限が36500日程度にあれば上限なしとみなす）。未完了タスクの現在位置を決める |
| 並び順 | 同じ空間内での表示順 |

### 日付が変わったときの振る舞い（派生計算でも、日次更新でもよい）

- 未完了タスク: 先送り日数 = max(0, 先送り日数 − 経過日数)
- 完了タスク: 表示位置（過去日数） = 今日 − 完了日
- つまり「翌日に自動で左へ／今日へ寄る」は、保存値の書き換えではなく
  「基準日（対象日）を絶対日付で持ち、表示位置を今日との差分で出す」実装でも達成できる。
  どちらの実装でも、利用者から見た振る舞いが一致すればよい

## 画面と操作

### 空間ビュー

- 表示は常に1空間だけ。空間は横一列につながった列として並び、スワイプ／ボタンでスライド移動する
- 空間のラベル:
  - 0: 「今日やる」
  - +n（未完了）: 「明日までやらない」「n日後までやらない」
  - −n（完了）: 「昨日完了」「n日前に完了」
  - 今日の空間では、その日の完了済みを下部に分けて表示する
- ナビゲーション範囲は、タスクが存在する空間まででよい。空の空間へは進めない

### ジェスチャ

| 操作 | 対象 | 動作 |
|---|---|---|
| 左右スワイプ | 入力エリアまわり（余白・ラベル等。入力欄そのものの上は文字選択を守るため対象外でよい） | 空間を1つ移動 |
| 左右フリック | タスク行 | そのタスクを1日分、先送り／戻す |
| シングルタップ | タスク行 | 詳細を開く |
| ダブルタップ | タスク行 | 完了にする |

- 空間スワイプとタスク行フリックは対象領域が異なるため、両立させる
- 空間移動のアニメーションは指への追随＋ページ単位スナップ（Trello 風）。端では抵抗感を付ける

### 詳細画面

- タイトル編集、詳細メモ編集
- 完了／未完了に戻す
- 先送りの変更（±1日ボタンと直接指定）
- 並び替え、削除

## 非機能・制約

- 保存はアプリ専用の保存領域に行い、再起動・再表示をまたいで保持される
- データは利用者個人のもので、他者と共有されない
- 説明文（使い方等）はデフォルトで閉じ、「？」ボタンからのツールチップ表示とする
- 初期データは空

## 対象外

- 複数人での共同編集、他のユーザーへのデータ共有
- 期限時刻（時分）の管理、繰り返しタスク、通知リマインダー
- 静的ページとしての公開（保存が必須のため対象外）
