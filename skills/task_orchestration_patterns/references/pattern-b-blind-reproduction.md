# パターンB 盲検再現

文脈を持たない再現役が、再現パッケージ（プロンプト／仕様書）だけを入力として成果物を再現し、文脈を持つ検証役が元の成果物や受け入れ基準と照合する型。テスト対象は再現物ではなく再現パッケージそのものであり、再現物は使い捨ての実験体である。パターンA（監査付き）が成果物の出来を直す型であるのに対し、この型はパッケージの書き方を直す型である。

他のパターンと決定的に違う点が1つある。1回の成功は「たまたま上手い再現役に当たった」だけの可能性が残るため、この型では成功しても止まらない。試行回数で指定された回数だけ、独立した試行を必ず全て実行し、項目ごとの通過率でパッケージの再現可能性を判定する。したがってこの型の回数パラメータは「失敗時のリテイク上限」ではなく「試行回数」である。

## 必須パラメータ

- 再現パッケージは、再現役への唯一の入力となる文書やURLである。再現役に渡すものが特定できなければ必須パラメータ不足として質問する。

- 照合基準は、元の成果物、および／または受け入れ基準のチェックリストである。比べる相手が示されていない場合は不足として質問する。照合基準は実行開始前に固定し、途中で動かさない。

- 試行回数は、独立した再現試行を何回実行するかを数で示す。全試行が合格しても、指定回数に達するまで試行を続ける（早期終了しない）。試行回数が1の場合は「1回成功した」以上のことは言えず、報告でもその限界を明示する。回数はコストと時間に直結するため、既定値で勝手に決めない。

- テスト成果物の処分は、検証後に削除するか残すかを明示する。実データや実運用の対象と混ざる恐れがある場合は、処分方法が決まるまで実行しない。

## 任意パラメータ

- 再現役の数は既定で1である。複数に作らせると、「たまたま上手い個体が再現できた」のか「誰がやっても再現できる」のかを分けられる。数を増やす前にユーザーに確認する。

- 厳しさは既定で機能等価である。見た目や文言の完全一致まで求める場合は、ユーザーの指定があったときに限る。

- 盲検の担保方法は、実行環境に応じてディレクターが指定する。サブエージェントがディレクターの文脈を引き継ぐ環境では盲検にならないため、その場合は「渡した依頼文だけを見て作る経路」（アプリ作成ビルダーなど）を再現役に使う。

## 質問のしかた

- 照合基準が曖昧な場合は、候補となる基準（元の成果物そのもの、受け入れ基準リスト、仕様書の項目など）を具体的に挙げて、どれを物差しにするかを確認する。

- 試行回数が未指定の場合は、回数の候補を示して選んでもらう。その際、回数が多いほど「たまたま成功しただけ」の可能性を潰せるが、コストも増えることを添える。

## 実行手順

- ディレクターは照合基準を先に読み、判定の観点を固定する。再現役には再現パッケージ以外の情報を一切渡さない。ディレクターが依頼文にパッケージ以外の説明や補足を足した時点で盲検は崩れるため、足さない。

- 試行の間、パッケージは凍結する。試行の途中でパッケージを改訂すると、試行同士が別の入力への反応になり比較できなくなるため、改訂は全試行が終わってから行う。

- 各試行は、必ず新しい文脈なしの再現役で行う。一度でも他の試行の内容や検証結果を見た再現役は盲検ではなくなっているため、使い回さない。再現役はパッケージだけから再現物を作り、自己申告を添えて納品する。自己申告は手順の適合の報告にとどめ、品質の保証として扱わない。

- 検証役は試行ごとに、再現物を実際に操作・確認し、照合基準の項目ごとに通過か不合格かを理由つきで判定する。前の試行の合否を次の試行の判定に持ち込まない。

- 全試行が終わったら、項目ごとに通過率（例：3試行中3回通過、3試行中1回通過）を集計する。全試行で落ちる項目はパッケージ側の問題である可能性が高く、試行によって結果が割れる項目は再現役側のばらつき（解釈の揺れ）を示す。

- 不合格の項目は、原因を次の3つに分類する。①パッケージの書き漏れや曖昧さ、②再現役の指示不遵守、③照合基準側の曖昧さや元の成果物との不整合。

- 直す対象は原則として①のパッケージである。パッケージを改訂したら、その改訂をユーザーに示す。改訂したパッケージは別バージョンであり、改訂後の再現可能性は改めて試行しない限り未検証であることを報告に明示する。再度の試行セットを行うかどうかは、ユーザーの指示に従う。③は勝手に解釈せずユーザーに上げる。

- 終了時は、全試行のテスト成果物を処分パラメータどおりに処理し、処分したかどうかを報告に含める。

## 報告の形

- 実行した試行回数と、照合項目ごとの通過率と判定理由、不合格の原因分類（①②③）、パッケージへの改訂点を示す。試行によって結果が割れた項目は、割れたこと自体を結果として残す。

- テスト成果物の処分結果を明記する。試行回数が1回の場合は、「再現可能性は未検証で、成功が偶然である可能性を排除できない」旨を明示する。
