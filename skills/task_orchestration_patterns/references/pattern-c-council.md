# パターンC 合議

判断基準の違う複数のメンバーが独立に判断し、あらかじめ決めた決め方で集約する型。マギシステムのように、立場の違いを多数決や統合の材料として残すために使う。

## 必須パラメータ

- 決めたい問いは、合議にかける意思決定を一文で示す。問いが論点の列挙で終わり、何を決めるのかが定まらない場合は不足として質問する。

- 人数は、メンバーの数を数で示す。2人以上を必須とする。

- 判断基準は、メンバー1人につき1つの判断軸を割り当てる一覧である。軸は性格や人柄ではなく、何を優先して評価するかで書く。人数と軸の数が一致しない場合は不足として質問する。

- 決め方は、多数決、全会一致、拒否権あり、議長統合のいずれか、またはその組み合わせで示す。未指定の場合は候補を提示して選んでもらう。既定値で勝手に決めない。

## 任意パラメータ

- 候補案は、問いが選択肢の比較である場合の選択肢一覧である。ユーザーが示していない場合、ディレクターが候補を作ってよいが、その場合は合議の前に候補案をユーザーに示す。

- 意見交換ラウンドは既定で1回である。独立判断の提出後に他のメンバーの判断を見て改訂する機会を指す。不要と指定されたら独立判断だけで集約する。

- 最終決定者は既定でユーザーである。合議の結果は推奨として示し、決定はユーザーが行う。議長統合を選んだ場合も、最終決定者をユーザー以外に変えるのはユーザーの指定があったときに限る。

## 質問のしかた

- 判断基準が人数分そろっていない場合は、足りない分の軸の候補を具体的に挙げて確認する。例えば収益性、実現可能性、利用者体験、リスクのように、問いに応じた候補を示す。

- 決め方が未指定の場合は、候補ごとの違いを短く添えて選んでもらう。

## 実行手順

- ディレクターは各メンバーへ、問い、候補案や判断材料、そのメンバー専用の判断軸だけを渡す。他のメンバーの軸や見解は渡さない。

- 各メンバーは独立に判断を提出する。結論、根拠、その軸から見たリスク、結論が変わる条件を含める。

- 意見交換ラウンドがある場合は、全員の判断が出そろった後に相互に開示し、各メンバーは改訂するか維持するかを理由つきで示す。

- ディレクターは決め方に従って集約する。多数決なら票の内訳を示し、拒否権が行使された場合はその理由をそのまま残す。

- 集約できない場合や同数で割れた場合は、決着したように見せず、両論と割れた理由をユーザーに上げて判断を仰ぐ。

## 報告の形

- メンバーごとの結論を判断軸と並べて示し、集約結果とその決め方の適用結果を示す。

- 少数意見は要約で潰さず、根拠つきで残す。不確実な点と、結論が変わる条件も添える。
