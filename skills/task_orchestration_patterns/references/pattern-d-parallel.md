# パターンD 並列

重視する観点の違う複数の調査役が独立に調べ、統合役が結果を束ねる型。1人の調査では視野が偏る広い問いに使う。

## 必須パラメータ

- 調べたい問いは、調査の対象と知りたいことを示す。対象の範囲が定まらない場合は不足として質問する。

- 人数は、調査役の数を数で示す。2人以上を必須とする。

- 重視する観点は、調査役1人につき1つの観点を割り当てる一覧である。観点同士が実質的に重なる場合は、重なりを指摘して割り当ての見直しを確認する。人数と観点の数が一致しない場合は不足として質問する。

## 任意パラメータ

- 範囲の境界は、対象期間、地域、情報源の種類などの絞り込みである。指定がなければ制限なしとして着手時に明示する。

- 統合後の形は、報告の形式や長さの希望である。指定がなければ、観点ごとの findings と統合結論を分けた標準形で報告する。

- 情報源の制限は、使ってよい情報源や避ける情報源の指定である。指定がなければ通常の検索と資料の読み取りを使う。

## 質問のしかた

- 観点が人数分そろっていない場合は、問いに合う観点の候補を具体的に挙げて確認する。例えば技術、市場、事例、リスクのように、問いの性質に応じた候補を示す。

- 問いの範囲が広すぎて観点で割り切れない場合は、範囲を絞る質問を先にする。人数を増やす提案は、ユーザーの確認を取ってからにする。

## 実行手順

- ディレクターは各調査役へ、問い、その担当の観点、範囲の境界、求める出力の形を渡す。他の調査役の観点や途中結果は渡さない。

- 各調査役は独立に調べ、観点に沿った findings、出典、確信度、調べ切れなかった範囲を提出する。

- 全員の提出がそろったら、ディレクターまたは統合役が統合する。一致した点、矛盾した点、誰の観点からもカバーされなかった空白を分けて整理する。

- 矛盾した点は平均や多数決で消さず、どちらの出典が何を根拠にしているかを示して残す。

- 調査の途中で、割り当てた観点では届かない重要な論点が見つかった場合は、人数を勝手に増やさず、論点と追加調査の要否をユーザーに確認する。

## 報告の形

- 観点ごとの findings を担当と並べて示し、その後に統合結論を示す。

- 矛盾点と未カバーの空白を、統合結論とは分けて明示する。
